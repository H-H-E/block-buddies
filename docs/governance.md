# Governance & Decision Making 🗳️

> How Block Buddies makes decisions, grows sustainably, and maintains quality.

---

## 🎯 Governance Philosophy

Block Buddies operates on principles of:

1. **Decentralized leadership**: Local chapters have autonomy within guidelines
2. **Transparent decision-making**: Major decisions are documented and explained
3. **Mission alignment**: Does this help teens teach kids CS through Minecraft?
4. **Safety first**: When in doubt, prioritize participant safety
5. **Sustainable pace**: Burnout helps no one

### Core Stewards

- Resolve conflicts escalated beyond working groups

**Curriculum Working Group**

**Safety Council**

**Operations Working Group**

### Chapter Coordinators

- Local decision-making authority
- Report to regional leads (when they exist)

## 📊 Decision Categories

### Level 1: Local/Individual

**Who decides**: Individual contributor or local coordinator  
**Examples**:
- A mentor's specific lesson approach
- Scheduling adjustments
- Minor doc improvements
- Local event planning

**Process**: Just do it (within guidelines)

### Level 2: Chapter/Regional

**Who decides**: Chapter coordinator, in consultation with affected parties  
**Examples**:
- New local partnerships
- Mentor onboarding in that area
- Local adaptation of materials
- Chapter-level policies

**Process**: 
1. Discuss with relevant stakeholders
2. Document decision
3. Notify working groups if broadly applicable

### Level 3: Working Group

**Who decides**: Relevant working group, aiming for consensus  
**Examples**:
- Curriculum changes
- Safety protocol updates
- Technology adoptions
- New contributor roles

**Process**:
1. Proposal submitted (see template below)
2. Discussion period (1-2 weeks typical)
3. Seek consensus; if blocked, escalate
4. Document outcome
5. Communicate to network

### Level 4: Core Stewards

**Who decides**: Core stewards with broad consultation  
**Examples**:
- Mission or values changes
- Major structural decisions
- Unresolvable conflicts
- Crisis response

**Process**:
1. Explicit agenda item
2. Input gathering from all stakeholders
3. Deliberation
4. Documented decision with reasoning
5. Broad communication

## 🌱 Growth & Scaling Protocols

### Adding New Chapters

**Prerequisites:**
- [ ] At least one committed adult coordinator
- [ ] Minimum 3 interested teen mentors  
- [ ] Safe venue identified
- [ ] Coordinator trained on Block Buddies approach
- [ ] Safety protocols understood and accepted

**Process:**
1. **Expression of interest**: Contact core team
2. **Orientation**: Review materials, discuss approach
3. **Coordinator training**: Complete training modules
4. **Pilot approval**: Green light from operations group
5. **Soft launch**: First cohort with close oversight
6. **Evaluation**: After first cohort, review together
7. **Full chapter status**: After successful pilot

### Curriculum Expansion

**Adding new modules/tracks:**
1. Proposal via curriculum working group
2. Alignment with CSTA standards (where applicable)
3. Pilot testing with volunteer pairs
4. Feedback integration
5. Documentation to standards
6. Release to network

**Adding new platforms (beyond Minecraft):**
1. Strong proposal demonstrating demand
2. Core steward approval (significant resource commitment)
3. Curriculum adaptation
4. Safety review
5. Pilot chapter
6. Broad rollout

### Partner Onboarding

**Institutional partners:**
1. Initial conversation (any coordinator can start)
2. Values alignment check
3. Pilot proposal for small collaboration
4. Formal partnership if pilot succeeds
5. Ongoing relationship management

### Contributor Progression

**Mentor → Lead Mentor → Coordinator pipeline:**

| Stage | Requirements | Who Approves |
|-------|-------------|--------------|
| New mentor | Complete training, matched | Any coordinator |
| Experienced | 2+ cohorts completed well | Local coordinator |
| Lead mentor | 4+ cohorts, trains others | Chapter coordinator |
| Chapter coordinator | Lead mentor + adult sponsor | Operations group |
| Regional lead | Multiple chapters + track record | Core stewards |

## ⚖️ Conflict Resolution

### Between Individuals

1. Direct conversation encouraged
2. If unresolved: local coordinator mediates
3. If still unresolved: escalate to working group

### Between Chapters/Regions

1. Direct coordinator conversation
2. If unresolved: operations working group
3. If fundamental: core stewards

### About Direction/Values

1. Raise with relevant working group
2. If systemic: bring to core stewards
3. All viewpoints documented

### Principles

- Assume good faith
- Address behavior, not character
- Focus on solutions
- Document for learning

## 🔄 Continuous Improvement

### Feedback Mechanisms

| Mechanism | Frequency | Who Participates |
|-----------|-----------|------------------|
| Session feedback | Each session | Mentors, mentees |
| Cohort retrospective | End of each cohort | All participants |
| Chapter health check | Quarterly | Coordinators + core |
| Network review | Annually | Everyone invited |

### Version Control

All significant documentation changes should:
- Use pull requests for review
- Include clear descriptions of changes
- Tag with relevant working group

### Learning & Adaptation

- We expect to make mistakes
- Mistakes are learning opportunities (when we learn)
- Document what didn't work and why
- Iterate, iterate, iterate

## 📋 Policies

### Change Management

| Change Type | Notice Required | Approval Required |
|-------------|-----------------|-------------------|
| Typo/grammar fixes | None | Any maintainer |
| Documentation improvements | None | Any maintainer |
| Process clarifications | None | Working group consensus |
| New optional resources | 1 week | Working group |
| Curriculum structure changes | 2 weeks | Curriculum WG |
| Safety protocol changes | 2 weeks | Safety council |
| Operational changes | 2 weeks | Operations WG |
| Mission/values changes | 4 weeks + | Core stewards |

### Voting (When Needed)

For formal decisions when consensus fails:
- Simple majority for operational matters
- 2/3 majority for significant changes
- Unanimous consent for mission/values

### Removal/Suspension

**For safety concerns**: Immediate action, process later
**For other issues**: Follow progressive approach
1. Informal conversation
2. Formal warning
3. Probationary period
4. Removal if pattern continues

**Appeals**: To next level of organization (like → regional → core)

## 📅 Governance Evolution

This governance structure is itself subject to evolution:

- Currently we're small and informal
- As we grow, we'll formalize where needed
- Resist premature bureaucracy
- Add structure only when necessary
- Regularly prune unnecessary process

**Review schedule**: Governance reviewed annually (or when pain points emerge)
