# Stage 2: Modpack Lab

> **LEGACY PATHWAY (superseded by V3 canon, 2026-08-23):** This document describes the retired V2 fluency-archetype model (tracks, S01-S08 spine, Do/Explain/Debug). It is preserved for the advanced pathway and historical reference only. For current truth see [Product & Pedagogy Canon](./canon/product-canon.md) or [Canon](./canon/product-canon.md).

## Stage Promise
Learners move from building systems inside Minecraft to safely inspecting, changing, testing, and explaining modded Minecraft systems. By the end, they can design a tiny curated modpack experience with a player promise, controlled changes, a test plan, documentation, and debug evidence.

## Prerequisites
- S08 pass or support-pass, or coordinator approval after equivalent evidence.
- Learner can follow a prepared Minecraft workflow without public-server chaos.
- Learner can test one change at a time with mentor support.
- Mentor has completed pack readiness checks before session time.

## Pilot Pack Contract
| Field | Value |
|---|---|
| Approved profile | Block Buddies Modpack Lab Pilot Profile |
| Minecraft version | 1.21.1 |
| Loader | Fabric |
| Pack version | pilot-0.1 |
| Download policy | No learner-selected random downloads during sessions |
| Multiplayer policy | Local/single-player or mentor-controlled LAN only |
| Reset policy | Every session starts from a known-good clean profile copy |
| Tech-support boundary | Planned lab diagnosis only; restore after bounded troubleshooting |

The pilot pack metadata is a curriculum contract. It can be replaced later by a real exported pack, but every replacement must preserve the same safety fields.

## Session Map
| Session | Title | Core concept | Minecraft output |
|---|---|---|---|
| S09 | Welcome to Modded Minecraft | Mods, modpacks, profiles, safe installs | Launch curated pack and identify changes |
| S10 | Recipe Radar | Information systems, UI, search, discoverability | Use recipe viewer to solve scavenger hunt |
| S11 | Resource Pack Remix | Representation, assets, visual design, accessibility | Modify/apply a small resource pack |
| S12 | Config Lab | Parameters, variables, balance, before/after testing | Change one safe config value and test effect |
| S13 | Rules Without Java | Data-driven rules, recipes, loot, tags, simple functions | Add or modify a recipe/reward/challenge rule |
| S14 | Dependency Dungeon | Dependencies, compatibility, versions, crash diagnosis | Fix a prepared missing/incompatible dependency |
| S15 | Contraption or Automation Mod | Systems, throughput, bottlenecks, mechanical reasoning | Build a small modded machine or automation chain |
| S16 | Mini-Modpack Capstone | Product design, testing, documentation, player experience | Present a tiny curated modpack experience |

## Concept Ladder
1. Observe a curated modpack before changing anything.
2. Use interface/search tools to query the system.
3. Change representation safely with resource packs.
4. Change one parameter and test before/after.
5. Change a data-driven rule without Java.
6. Diagnose one prepared dependency/version problem.
7. Build and debug a visible modded system.
8. Curate, test, document, and present a tiny experience.

## Do Not Let This Become Tech Support
- Do not troubleshoot random real crashes during paid learner time.
- Do not let learners browse unknown mod sites or download arbitrary files.
- Do not switch Minecraft version, loader, or launcher workflow mid-session.
- Do not debug beyond the session boundary; restore a known-good profile and keep the learning loop moving.
- Use prepared known-broken profiles only when the lesson is dependency/config diagnosis.

## Completion Rubric
A Stage 2 curriculum packet is complete when each S09-S16 runbook includes pack metadata, early win, core quest, track variations, Do/Explain/Debug gates, fallback moves, hint ladder, evidence, parent-safe summary, student checklist, and a tech-support boundary. Typed app data must preserve Stage 2 metadata rather than flattening it into generic strings.
