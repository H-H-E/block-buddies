# Session 5: Extension Task and Side-Quest Unlocks

## Objective
By end of session, learner can extend a prior build with one new capability and validate behavior with evidence.

## Loop Plan
- Hook (5m): showcase upgraded version.
- Worked Example (5m): mentor adds one extension quickly.
- Core Quest (20m): learner adds required extension.
- Side Quest or Fallback (10m): unlock stretch/expert or simplify.
- Exit Ticket (5m): learner picks next improvement path.
- Intervention limits: Fluency 0 (30s), Fluency 1 (2m), Fluency 2 (5m).

## Early Win
Existing build from Session 4 is loaded and verified immediately.

## Tier 1 Core Quest
Add one extension and test it:
- `A`: second texture family or shader tweak.
- `B`: repeaters/timing control or SU budget change.
- `C`: second permission tier or whitelist rule.

Expected output: extension is verified in one live test cycle.

## Track-Specific Worked Examples (A/B/C)
- `A` Visualist: add alternate texture variant and verify asset swap works.
- `B` Mechanist: add timing control and verify signal behavior changes as expected.
- `C` Operator: add least-privilege permission tier and verify access outcome.

## Tier 2 Stretch Side Quest
- Unlock: Fluency >= 1 and MG-S04-DEBUG pass
- Outcome: integrate one cross-concept dependency.

## Tier 3 Expert Side Quest
- Unlock: Fluency = 2 and MG-S05-DO pass
- Outcome: design and run own test checklist.

## Branch Minute Budgets
| Path | Hook | Worked Example | Core Quest | Side/Fallback | Exit Ticket | Total |
|---|---:|---:|---:|---:|---:|---:|
| Core + fallback | 5 | 5 | 20 | 10 | 5 | 45 |
| Core + stretch | 5 | 5 | 20 | 10 | 5 | 45 |
| Core + expert | 5 | 5 | 18 | 12 | 5 | 45 |

## Fallback Path
Trigger when blocked >= 7 total minutes or extension fails verification twice.

Recovery ladder order:
1. Guiding question.
2. Specific hint.
3. Model one step.
4. Fallback mini-win.

Fallback mini-win: single variable change + immediate verification.

## Mastery Gates
- Do: extension works in live test.
- Explain: learner predicts effect before applying change.
- Debug: learner reverts unsafe change and restores working state.
- Pass rule: `Do=pass/support-pass` and at least one of `Explain` or `Debug=pass/support-pass`.
- If `Debug=fail`: start S06 with debug retrieval.
- If `Do=fail`: repeat S05 with reduced extension scope.
