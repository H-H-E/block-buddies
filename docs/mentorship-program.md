# Mentorship Program Structure (V2)

## Program Model

- Format: 1 mentor : 1 mentee
- Session length: 45 minutes
- Program spine: 8 session indexes (`S01..S08`)
- Pacing: personalized by mastery gates, not fixed weekly lockstep

## Session Cadence

- Recommended: weekly same-day cadence
- Allowed: flexible rescheduling when needed
- Rule: if momentum gap > 2 weeks, run a retrieval mini-session first

## Matching Inputs

From mentees:
- Fluency signals
- Archetype preference (A/B/C)
- Profile confidence (`high|medium|low`)
- Availability and accessibility needs

From mentors:
- Track strengths
- Comfortable fluency support range
- Availability and safety commitments

## Matching Priorities

1. Availability overlap
2. Safety and communication fit
3. Track alignment
4. Fluency support fit

## Mandatory Read-Before-Match Fields

- Learner profile code (`fluency-archetype`)
- Learner profile confidence
- Learner accessibility notes
- Mentor supported fluency levels
- Mentor mismatch-escalation agreement

## Session Operations

Every session requires:
- Runbook ID
- Do/Explain/Debug outcomes
- Time-cap/fallback log
- Reassessment trigger flags (if any)
- Mentor mismatch flag (if any)
- Next-session condition

## Escalation Rules

- Repeated `Do` failures: lower scaffolding and re-run session theme
- Repeated `Debug` failures: mandatory retrieval block at next session start
- Repeated attendance issues: coordinator intervention
- Repeated mentor mismatch signals: reassessment + rematch review within 48 hours

## Reassessment and Rematch Flow

1. Mentor logs mismatch or low-confidence evidence.
2. Coordinator checks profile code + confidence + trigger flags.
3. Coordinator runs reassessment mini-session.
4. If mismatch persists, rematch based on track and fluency support fit.

## Mentor Support

- Pre-service training on V2 pedagogy
- Shared troubleshooting office hours
- Structured session log review
- Coordinator support for rematch/escalation
