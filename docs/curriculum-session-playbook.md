# Curriculum Session Playbook (V2)

This playbook complements the canonical runbooks with a fast mentor-facing execution layer.

## Universal Session Contract

- Keep fixed loop order: Hook -> Worked Example -> Core Quest -> Side/Fallback -> Exit Ticket.
- Enforce fluency intervention limits (`0=30s`, `1=2m`, `2=5m`).
- Switch to fallback mini-win at 7-minute hard cap.
- Score Do/Explain/Debug and set next-session condition before close.

## S01-S08 Mentor Quick Reference

### S01 Diagnostic, Trust, First Win
- Must finish: profile code + confidence + first-win artifact.
- Common risk: archetype guess based on preference only.
- Quality check: one behavior evidence each for fluency and archetype.

### S02 Safety, Backups, Recovery
- Must finish: named backup + restore verification.
- Common risk: archive created but never validated.
- Quality check: learner explains why rollback order matters.

### S03 Track Onboarding
- Must finish: one A/B/C starter artifact.
- Common risk: switching tracks mid-session without logging rationale.
- Quality check: one cause/effect explanation in learner language.

### S04 Foundation + Debug Drill
- Must finish: seeded fault corrected with evidence.
- Common risk: fix applied without isolating cause.
- Quality check: learner states dependency relationship before closure.

### S05 Extension + Side-Quest Unlocks
- Must finish: extension with test proof.
- Common risk: side quest replacing core extension.
- Quality check: prediction-before-change captured.

### S06 Troubleshooting Studio
- Must finish: root cause + verified fix.
- Common risk: trial-and-error loops without elimination logic.
- Quality check: one false-cause elimination note.

### S07 Capstone Build + Mentor Fade
- Must finish: scoped capstone slice with demonstration proof.
- Common risk: over-scoped capstone and incomplete exit.
- Quality check: reduce scope early when deadline risk appears.

### S08 Demo, Reflection, Verification
- Must finish: structured demo + continuation plan.
- Common risk: narrative demo without concrete evidence.
- Quality check: concept transfer and one live change/debug response.

## Cross-Track Evidence Minimums

- Visualist (`A`): path/file validity + visual output proof.
- Mechanist (`B`): input/output behavior proof + reliability note.
- Operator (`C`): config diff proof + recovery verification.
